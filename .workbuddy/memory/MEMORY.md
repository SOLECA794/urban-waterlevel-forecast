# 项目长期记忆：城市内涝（积水）水位预测预警系统

## 项目性质
老师布置的课程/毕设级 **demo**，本机演示 + 文档交付。工作区 `D:\Desktop\waterLevelForcasting`。

## 已定的口径（不要反复重新讨论）
- **本期交付 = 脚手架 + 可运行原型**。老师说：搭骨架即可，**不严格要求实际模型**，数据模拟即可。
- **本期不考核预测精度**。评判的是结构完整性、接口清晰度、链路能否跑通、留白是否规范。
- **不引入任何有安装风险的依赖**：prophet（cmdstanpy 在 Windows 安装失败率高）、torch（体积大）、celery/redis、时序数据库集群、地图（合规审图号 + 政务内网无公网瓦片）。Python 锁 3.11。
- 预测模型是**占位实现**（Naive + LinearResponse，纯 numpy），Prophet / LightGBM / TCN 仅留实现位。**这不是技术判断的回退，是"决策依据从算法优劣换成骨架能否跑起来"的结果。**

## 三层交付边界（核心框架）
- **骨架层（做实）**：目录结构、模块边界、接口契约、数据模型、配置外置、异常处理、日志
- **原型层（形态到位，逻辑可简）**：四个前端页面、全部 REST 接口、predict → alert 演示链路
- **占位层（留白）**：真实数据源、真实算法、推送、权限、自动校准

## 硬性工程约定
- **占位 ≠ 缺失**：留白必须有 ① 完整接口签名 ② 符合契约的返回 ③ `# EXT-POINT(类型): 说明` 标注，类型限 `DATASOURCE / MODEL / ALGORITHM / INTEGRATION`。`grep EXT-POINT` 须能列出全部待填位点。
- 两个核心抽象：`DataSource`（SimulatedSource 真实现 / RealSourceAdapter 占位）、`ForecastModel`（多模型可切换，支撑场景 S7「模型可插拔演示」）
- **数据库必须含 `forecast_point` 逐点明细表**（含 `actual_level` 事后回填）。虽属占位功能，但将来补做要重构存储层，不能省。
- REST 统一 `/api/v1`，响应统一 `{code, message, data}`；前端禁止仅凭 HTTP 200 判成功。
- 前端 mock 双通道（`VITE_USE_MOCK`），后端不启动时四页面仍可演示。
- 前端 Vue 3 + Vite + Element Plus + ECharts，不引入 Pinia；本期不做地图。
