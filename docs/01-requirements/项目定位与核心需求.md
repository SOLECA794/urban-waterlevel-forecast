# 项目定位与核心需求

> 本文档从老师需求书原文出发，提炼项目的定位和必须交付的核心能力。

## 1. 项目定位

这是一套**面向城市内涝防治的 AI 预测预警系统**，不是监测看板，也不是单纯的算法 demo。

核心定位三句话：
1. **预测**：用 AI 算法提前算出来未来 1/3/6/12 小时的水位，不是只看现在的水位
2. **预警**：算出来之后自动判等级、发通知，不是让人盯着曲线猜
3. **智能**：融合多源数据、滚动自我修正、Agent 主动值班，不是静态跑一遍模型

## 2. 核心需求（按老师原文拆解）

### 2.1 多源数据融合
老师要求接入四类数据：
- 历史降雨
- 历史积水
- 实时监测点（水位/雨量）
- 气象预报

并对这些异构数据做统一的**特征工程处理**，输出一份统一数据集供模型用。

### 2.2 趋势预测模型
老师原文："融合时序预测模型、AI算法、智能体等进行分析"。

重点预见期：**1 小时、3 小时**（短临，防汛最有用）。
扩展预见期：6 小时、12 小时。

这不是单一模型，是三者融合：
- 时序模型：抓水位/降雨的时间规律
- AI 算法：从历史数据中学非线性关系
- 智能体：决定什么时候预测、用哪个模型、怎么修正

### 2.3 预警等级研判
预警不能只看"水位超没超阈值"，老师要求三个因子联合：
- **预测水位**：峰值多高
- **持续时间**：超阈值持续多久（短时超一下不报警，持续超才报警）
- **变化趋势**：还在涨还是在退（加速上涨要升级，下降可以降级）

等级数量和阈值必须**按管理规则可配置**，不能写死。

### 2.4 多源协同修正
预测不是算一次就完，要滚动校正：
- 用最新实时监测数据修正
- 用最新气象预报修正
- 用已发生的积水事件修正

并且保留**预测版本 vs 实际值**的对比记录，用来评估模型准不准。

### 2.5 结果应用
预测结果必须在两种形态上看：
- **一张图**：全城市一张图，站点按预警等级着色
- **趋势曲线**：单站历史+预测+阈值线

达到预警条件时要**联动发布**：消息推送、信息屏、其他渠道。

### 2.6 模型校准
系统要能自我进化：
- 拿实际发生的积水事件和预测结果对比
- 定期重训 / 调参 / 改规则
- 在线学习是可选，不是必须

## 3. 项目要解决的真实问题

防汛值班员的痛点：
- 看到涨水时已经来不及 → 系统要提前 1-3 小时给出预警
- 多站点来回切容易漏 → 一张图总览
- 不知道预警怎么算的 → 要给触发原因
- 误报太多导致"狼来了" → 三因子联合研判降低误报

## 4. 本期交付边界

老师要的是**模型软件**部分，硬件（传感器、信息屏）后续一起制定方案。

所以本期：
- 算法链路必须真（数据融合→预测→研判→修正→可视化）
- 数据源可以模拟（等硬件接入后换适配器）
- 发布渠道先做站内弹窗，短信/信息屏留接口
