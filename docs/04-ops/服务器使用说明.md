### 3.3 远程执行命令（云助手）完整流程【实测】

```bash
# ① 下发命令（--CommandContent 传【原始脚本文本】，CLI 会自动 base64）
aliyun ecs RunCommand --RegionId cn-hangzhou --InstanceId.1 i-bp14x7n5r7pxvmedxx57 \
  --Type RunShellScript --CommandContent "$(cat myscript.sh)" \
  --Name my-task --Timeout 120
# 返回 {"CommandId":"c-xxx","InvokeId":"t-xxx",...} → 记下 InvokeId

# ② 轮询结果（status: Running → Success/Failed）
aliyun ecs DescribeInvocationResults --RegionId cn-hangzhou --InvokeId t-xxxxx

# ③ 解码输出：JSON 路径是 Invocation.InvocationResults.InvocationResult[]，
#    其中 Output 字段是 base64，用 node 解码：
node -e "const d=JSON.parse(require('fs').readFileSync(process.argv[2],'utf8'));const r=(((d.Invocation||{}).InvocationResults)||{}).InvocationResult||[];console.log('STATUS:',r[0].InvocationStatus,'EXITCODE:',r[0].ExitCode);if(r[0].Output)process.stdout.write(Buffer.from(r[0].Output,'base64').toString('utf8'))" -- result.json
```

保存下来的解码脚本（本机 `C:\Users\34511\.local\aliyun-cli\decode.js`，用法 `node decode.js <结果文件>`）：

```js
const fs=require('fs');
const [file]=process.argv.slice(2);
const d=JSON.parse(fs.readFileSync(file,'utf8'));
const r=(((d.Invocation||{}).InvocationResults)||{}).InvocationResult||[];
if(!r.length){ console.log("STATUS: none"); process.exit(0); }
console.log("STATUS:", r[0].InvocationStatus, "EXITCODE:", r[0].ExitCode);
if(r[0].Output) process.stdout.write(Buffer.from(r[0].Output,'base64').toString('utf8'));
if(r[0].ErrorInfo) console.log("ERR:", r[0].ErrorInfo);
```

### 3.4 传大文件到服务器（无 SSH / OSS 未开通时）【实测，62 块零丢失】

账号未开通 OSS（创建 bucket 报 403 UserDisable），831KB 部署包用「分块 RunCommand」传输：

```bash
# 本地：base64 后按 18000 字符分块（编码后 24000 < 24576 上限；18000 实测过，22000 失败）
base64 -w0 waterlevel-deploy.tar.gz > tar.b64
split -b 18000 tar.b64 parts/p_

# 每块下发一条 RunCommand（脚本两行）：
#   mkdir -p /root/wlparts
#   printf '%s' '<块内容>' > /root/wlparts/p_001
# 全部下发后服务器上拼装：
#   cat /root/wlparts/p_* | base64 -d > /root/waterlevel-deploy.tar.gz
#   md5sum /root/waterlevel-deploy.tar.gz   ← 与本地比对
```

一次性文件也可以用 Workbench 终端的上传按钮（§2.1），不需要脚本。

```bash
aliyun=... # 或全路径 "$HOME/.local/aliyun-cli/aliyun.exe"

aliyun ecs AuthorizeSecurityGroup --RegionId cn-hangzhou \

aliyun ecs RevokeSecurityGroup --RegionId cn-hangzhou \
  --SecurityGroupId sg-bp1hmlbq4r4ut8dqgplt \
  --IpProtocol tcp --PortRange 8099/8099 --SourceCidrIp 0.0.0.0/0 \

aliyun ecs DescribeSecurityGroupAttribute --RegionId cn-hangzhou \
  --SecurityGroupId sg-bp1hmlbq4r4ut8dqgplt --NicType intranet
```

- 改完立即生效，无需重启实例

## 6. 踩坑点大全（血泪经验，每条都真实踩过）

### 6.1 Git Bash 会改写 `/root` 之类的路径参数

- **现象**：`--TargetDir /root/wltest` 传到云端变成了 `D:/Program Files/Git/root/wltest`，文件发到了奇怪的地方
- **原因**：Git Bash（MSYS）对以 `/` 开头的参数做路径转换
- **解决**：命令前加 `MSYS_NO_PATHCONV=1`，例如 `MSYS_NO_PATHCONV=1 aliyun ecs SendFile ... --TargetDir /root/x`；写在多行脚本文本内部的路径不受影响

### 6.2 云助手命令内容有 24KB（base64 后）上限

- **现象**：`CmdContent.ExceedLimit`；实测 18000 字符原始内容可过，22000 失败
- **解决**：大内容按 ≤18000 字符分块多次下发（见 §3.4）；831KB 包 = 62 块

### 6.3 aliyun CLI 会自动做 base64 编码

- **现象**：自己先 `base64 -w0` 再传 `--CommandContent`，服务器上执行的是乱码，报 exit 127
- **原因**：CLI 对 CommandContent / SendFile.Content 自动编码，自己再编一层就双倍了
- **解决**：一律传**原始文本**，编码交给 CLI

### 6.4 DescribeInvocationResults 的 JSON 路径和输出编码

- 结果路径是 `Invocation.InvocationResults.InvocationResult[]`（不是 `InvocationResults.InvocationResult[]`，猜错会一直读到空）
- `Output` 字段是 base64，要解码（用 §3.3 的 decode.js）
- 状态值：Running → Success / Failed（**"Success" 不等于 "Finished"**，轮询判断条件要包含两者）

### 6.5 服务器默认 python3 是 3.6

- `python3` = 3.6.8，`pip 9.0.3`；现代依赖装不上
- **解决**：一切显式 `python3.11`；venv 用 `python3.11 -m venv`；start.sh 用 `PYTHON_BIN=python3.11` 环境变量

### 6.6 pip 镜像源选择

- 清华源 `pypi.tuna.tsinghua.edu.cn` 在这台服务器上 **403**
- 内网源 `mirrors.cloud.aliyuncs.com` 对 curl 不稳（000）
- **实测可用**：`https://mirrors.aliyun.com/pypi/simple/`（公网阿里云镜像，200）
- pip 报 "from versions: none" 基本都是索引连通性问题，不是版本问题

### 6.7 账号未开通 OSS

- `aliyun oss mb` 报 403 `UserDisable`（Ec=0003-00000801）——整个 OSS 服务未激活
- **解决**：要么控制台开通 OSS（免费，按量计费极低），要么一直用 §3.4 分块传输 / Workbench 上传

### 6.8 后台进程要脱离云助手会话

- 云助手命令结束时可能回收子进程组
- **解决**：`setsid nohup ... < /dev/null > log 2>&1 &` 三件套（水位系统就是这姿势起的，已验证能长期存活）

### 6.9 Windows 命令行 32K 长度限制

- 给 aliyun.exe 传超长参数（如整段脚本/大块文本）超过约 32767 字符会被截断/失败
- **解决**：分块（§6.2 的 18000 字符已经留了余量）

### 6.10 内存紧张，加服务前先看水位

- 2GB 内存与 java/minio/redis/另一台 uvicorn 共享；装完依赖后 available 约 900MB
- **习惯**：`free -m` 先看 `available` 列；不要在这台机上再堆大内存服务

### 6.11 安全组规则 ≠ 端口在监听

- 排查"访问不通"分两半：安全组有没有放行（§4.3 查规则）+ 服务器上有没有进程在听（`ss -tlnp | grep 端口`）+ 应用自身是否健康（curl 127.0.0.1:端口）

### 6.12 node 读取脚本参数的坑

- `node -e "..." arg` 里参数是 `process.argv[1]`；`node script.js arg` 里是 `process.argv.slice(2)[0]`（argv[1] 是脚本自身路径）——写解码脚本时混用会拿脚本自己当 JSON 解析

### 6.13 已知待办 / 建议

- [ ] **轮换 AccessKey**（曾明文出现在对话中）
- [ ] 3389 端口规则对 Linux 无用，建议在控制台删除
- [ ] 如需限制 8095 的访问范围，把规则源从 `0.0.0.0/0` 改为自己出口 IP/32
- [ ] 长期可考虑：启用已安装的 nginx 做反代 + 80 端口 + HTTPS
