## 0. 设计目标与边界

### 0.1 目标

解决评审中确认的 5 个问题：① 卡片墙无视觉节奏 ② 核心数字缺参照语境 ③ 页面间无叙事链 ④ 图表缺品牌感 ⑤ 状态反馈缺失。

一句话目标：**让演示第一屏有重点、核心数字有语义、页面之间形成"态势 → 分析 → 处置"的叙事链。**

### 0.2 明确不做（守住 demo 边界）

| 不做项 | 原因 |
|---|---|
| 响应式 / 移动端适配 | 演示固定大屏（≥1280px） |
| 暗色主题 | 无需求 |
| 炫技动效 / 复杂交互动画 | 与"防汛值班系统"气质不符 |
| 地图可视化 | 前文已定：政务内网无瓦片 + 涉图审 |
| 组件库更换 / 重构 | Element Plus 够用，重写是负资产 |
| 后端接口、数据结构改动 | 纯前端精修，接口零变化 |

## 1. 设计原则（5 条，实施时逐条对照）

| # | 原则 | 落地要求 |
|---|---|---|
| P1 | **态势优先** | 每个页面第一屏首先呈现"现在该关注什么"（预警点位/生效中预警），而非全量信息 |
| P2 | **数字有参照** | 任何核心数值必须带语义上下文：当前水位必须显示"距下一等级阈值还差多少"，禁止孤立数字 |
| P3 | **叙事成链** | 全站叙事链：`降雨 → 水位 → 预测 → 预警 → 处置`。总览=态势，详情=分析，预警中心=处置记录；页面层级与叙事顺序一致 |
| P4 | **反馈有节奏** | 每个异步动作具备三态：加载中 / 空态 / 结果态；不得出现无反馈等待或裸空表 |
| P5 | **品牌一致** | 全站只使用本文档 §2 定义的 Token；品牌蓝=系统/主操作，预警四色=仅预警语义，不得混用 |

| `--alert-orange` | #FF9800 | 仅橙色预警语义 |
| `--alert-red` | #F44336 | 仅红色预警语义 |
| `--status-ok` | #4CAF50 | 正常/成功/已解除 |

**使用边界（新增硬规则）**：修正后预测线 = 橙色实线（预示最终建议）；原始预测线 = 品牌蓝虚线（预示模型初值）；置信区间带 = 品牌蓝 8% 透明度。任何场景禁止互换。

### 2.2 字体层级

| 层级 | 规格 | 用途 |
|---|---|---|
| H1 页面标题 | 20px / 600 | 详情页点位名、设置页区块标题 |
| H2 区块标题 | 15px / 600 | el-card header、态势条标题 |
| 卡片标题 | 14px / 600 | 卡片名称 |
| 正文 | 13px / 400 | 表格、说明 |
| 辅助 | 12px / 400 | .muted |
| 数字展示 | 30px / 700 | 当前水位主数字（沿用 StationCard） |
| 数字强调 | 22px / 700 | 态势条统计数字 |

### 2.3 间距节奏

| Token | 值 | 用途 |
|---|---|---|
| 页面外边距 | 20px | `.page` 统一 padding: 16px 20px 保持 |
| 区块间距 | 16px | 卡片之间（现有 14px 统一为 16px） |
| 卡片内边距 | 14–16px | el-card body |
| 行内间距 | 8px / 12px | 标签组、按钮组 |

### 2.4 形状与层级

- 圆角：卡片 6px（el-card 默认）；控件 4px
- 卡片层级：普通信息卡 `shadow="never"` + 1px `--line` 边框（el-card 默认即有）；**预警点位卡/重点卡加左侧 4px 色条**（等级色）
- 阴影：仅交互反馈使用（hover 时 StationCard 保持 `shadow="hover"`）

### 2.5 组件级规范（全站统一）

| 规范 | 要求 |
|---|---|
| 表格 | `size="small"`、行 hover 高亮、`#` 列宽 70 |
| 等级标签 | 一律使用 `AlertBadge`（含参考级样式），禁止另写 |
| 主/次按钮 | 主操作 `type="primary"`；次级 `plain`；危险 `danger plain` |
| 空态 | 一律 `el-empty`，带业务文案（见 §4.2） |
| 加载 | `v-loading`，遮罩时提示文案 |
