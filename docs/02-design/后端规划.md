## 4. 核心抽象（Port）

### 4.1 DataSource

```python
class DataSource(Protocol):
    async def connect(self, config: dict) -> SourceInfo: ...
    async def disconnect(self) -> bool: ...
    async def start_stream(self, sink: Callable[[DataBlock], Awaitable[None]]) -> bool: ...
    async def stop_stream(self) -> bool: ...
    async def get_status(self) -> SourceStatus: ...
    async def get_series(self, station_id: int, hours: int) -> pd.DataFrame: ...
```

状态机：`DISCONNECTED → CONNECTING → READY → STREAMING`，异常转 `ERROR`，恢复后自动重连。

### 4.2 ForecastModel

```python
class ForecastModel(Protocol):
    name: str
    version: str
    def fit(self, history: pd.DataFrame) -> None: ...
    def predict(self, window: pd.DataFrame, horizon_min: int) -> ForecastResult: ...
    def describe(self) -> ModelMeta: ...      # 供 /api/v1/models 返回
```

`ForecastResult` 结构与将来真模型**完全一致**：`points`（含 t / level / lower / upper）、`peak_level`、`peak_time`、`confidence_interval`、`model_id`、`inference_ms`。

**占位模型**：
- `NaiveModel`：持久性模型，预测值 = 当前水位（作为最朴素的对照）
- `LinearResponseModel`：`Δlevel(t+h) = Σ wᵢ·rain(t−i) − k·(level − base)`，体现降雨驱动、滞后响应与退水，约二十行 numpy 代码，演示曲线形态可信

两个模型并存即支撑场景 **S7「模型可插拔演示」**：切换模型，曲线变化，业务代码不动。

### 4.3 Tool（V1.2 新增，本期做实）

```python
class Tool(Protocol):
    name: str
    description: str                    # 给 LLM 看的用途说明
    parameters: dict                    # JSON Schema
    risk_level: Literal["L0","L1","L2"]
    async def execute(self, **kwargs) -> ToolResult: ...
```

`ToolRegistry` 提供 `register` / `list` / `get` / `invoke`（含 risk_level 强制校验）。工具清单见 V1.2 §4.3。

### 4.4 Agent（V1.2 新增，本期占位）

```python
class Agent(Protocol):
    async def chat(self, session_id: str, message: str) -> AsyncIterator[AgentEvent]: ...
    async def get_session(self, session_id: str) -> AgentSession: ...
```

本期 `EchoAgent`：接收消息 → 用关键词匹配选中 Tool → 执行 → 把结果包装成回答。**即使没有 LLM，也能演示完整的"提问 → 选工具 → 执行 → 回答"链路**。

> 这是 **Agent-B（交互智能体）**。系统另有 **Agent-A（预测编排智能体）**，见 §4.5。两者通过 `forecast_decision` 表与 `explain_forecast` 工具打通。

### 4.5 ForecastOrchestrator（V1.3 新增，本期做实）—— 即 Agent-A

需求书"时序预测模型 + AI 算法 + **智能体**"中的"智能体"，语义是**模型具备自适应与自融合能力**，与 §4.4 的对话式 Agent 不是一回事。为避免语义错位，两者并存。

```python
class ForecastOrchestrator(Protocol):
    def decide(self, ctx: ForecastContext) -> ForecastDecision: ...
```

`ForecastDecision` 含五项决策，**全部记录、全部可解释**：

| # | 决策 | 输入依据 | 本期规则（示例） |
|---|---|---|---|
| D1 | 模型自适应选择 | 预见期、数据充足度、各模型近期误差 | 数据不足 → Naive；否则 LinearResponse；6h/12h 强制启用预报输入 |
| D2 | 多源融合权重 | 各源质量（延迟、缺失率、近期偏差） | `w ∝ 1/(1 + 近期偏差)`，归一化 |
| D3 | 修正策略 | 当前新息大小、数据新鲜度 | 新息 > 阈值 → 启用修正，`α = 0.6` |
| D4 | 置信区间自适应 | 近期误差、预见期长度 | `宽度 ∝ 近期RMSE × √h` |
| D5 | 降级决策 | 数据源状态 | 断流 → Naive + 标注"数据延迟" |

**本期实现 `RuleBasedOrchestrator`：纯 Python 规则，零依赖、无需 LLM、无需联网。** 将来可升级为 bandit/RL 选模型或 LLM 生成策略，实现替换不改调用方。

### 5.2 关键 DDL（核心部分）

```sql
CREATE TABLE station (
  station_id   INTEGER PRIMARY KEY,
  station_code VARCHAR(32) UNIQUE NOT NULL,
  station_name VARCHAR(64) NOT NULL,
  location     VARCHAR(128),
  source_id    INTEGER,
  threshold_blue   REAL, threshold_yellow REAL,
  threshold_orange REAL, threshold_red    REAL,
  base_level   REAL,          -- 晴天基流水位，供 LinearResponse 使用
  response_k   REAL,          -- 退水系数
  enabled      BOOLEAN NOT NULL DEFAULT 1,
  create_time  DATETIME NOT NULL, update_time DATETIME NOT NULL

CREATE TABLE forecast_point (
  forecast_id  INTEGER NOT NULL REFERENCES forecast(forecast_id),
  lead_minutes INTEGER NOT NULL,
  target_time  DATETIME NOT NULL,
  pred_level_raw REAL NOT NULL,        -- 模型原始输出（V1.3）

  decision_id    INTEGER PRIMARY KEY,
  forecast_id    INTEGER NOT NULL REFERENCES forecast(forecast_id),
  selected_model VARCHAR(32) NOT NULL, -- D1
  fusion_weights TEXT,                 -- D2，JSON
  revision_alpha REAL,                 -- D3
  ci_scale       REAL,                 -- D4
  degraded       BOOLEAN,              -- D5

CREATE TABLE alert (

  reason      TEXT,
  peak_level  REAL, peak_time DATETIME,
  lead_minutes_advantage INTEGER,      -- 预警提前量（较阈值报警提前的分钟数）
  is_reference BOOLEAN DEFAULT 0,      -- V1.3：6h/12h 长预见期预警标记「参考级」
  alert_time  DATETIME NOT NULL,
  resolve_time DATETIME,

CREATE TABLE flood_event (
```

## 7. 数据治理与特征工程

| 环节 | 规则 |
|---|---|
| 清洗 | 超出物理量程或与前点变化率超阈值 → 标记异常并按缺失处理 |
| 对齐 | 统一重采样到 5 min（可配置），多源按时间戳外连接 |
| 缺失 | 短缺失（≤3 点）线性插值；长缺失标记 `gap` 并降低该窗口置信度 |
| 特征 | 滑动窗口水位统计、累计降雨（1/3/6/12h）、雨强峰值、水位变化率、预见期降雨预报、小时/季节特征 |

特征工程为**独立模块**，输入 DataFrame、输出 DataFrame，契约清晰、可单测——这是将来接真模型时唯一需要扩展的地方。

### 7.5 多源协同修正（V1.3 新增）—— `ForecastRevisionService`

需求书原文："多源协同修正：滚动校正（结合实时监测、最新预报、已发生事件）"。**"滚动预测"（重新算一遍）不等于"滚动校正"（用已发生的事实修正尚未发生的预测）**，此处补齐显式设计。

**三类触发**

| 触发 | 对应需求书措辞 |
|---|---|
| T1 新实测到达 | 实时监测 |
| T2 新预报到达 | 最新预报 |
| T3 事件状态变化（进入退水期 / 已记录内涝事件） | 已发生事件 |

**算法：多源加权新息 + 时间衰减**

```
# 1) 各源新息
e_level = actual_level(t_now) - predicted_level(t_now)
e_rain  = Σ(actual_rain - predicted_rain)   # 最近窗口
e_fcst  = 最新预报量 - 上一版预报量

# 2) 多源加权合成（权重来自 Agent-A 的 D2 融合权重）
e = w_level·e_level + w_rain·e_rain + w_fcst·e_fcst

# 3) 对未发生时段做衰减修正
corrected(t) = predicted(t) + α·e·ρ^(Δt)      # Δt = t - t_now > 0
#   α 修正强度（Agent-A D3 决策，默认 0.6）
#   ρ 时间衰减（默认 0.85/步）：越远的未来修正越少

# 4) 置信区间随预见期展宽
width(t) = width_raw(t)·(1 + β·Δt)
```

**存储**：修正量写入 `forecast_point.revision`，原始值保留在 `pred_level_raw`。

**与"在线学习"的关系**（此处给出明确取舍，不留含糊）：

| 层次 | 做法 | 本期 |
|---|---|---|
| 预测级在线适应 | 本节的新息修正——不改模型参数，只修正本次输出 | ✅ 做实 |
| 模型级在线学习 | 增量训练更新模型权重 | ❌ **不做**：小样本强非平稳场景易发散，一旦发散整个演示崩；而预测级修正可随时关闭，失败也只是回到原始预测 |

**演示价值**：详情页同时画原始预测（细虚线）、修正后预测（粗虚线）、实测（实线），修正效果一眼可见。

## 8. 模拟数据生成

与 `LinearResponseModel` **共用同一套参数**（降雨响应权重、滞后、退水系数、基流水位）：

```
降雨事件（泊松触发 + 雨强时程曲线）
  → 有效降雨 = 降雨量 × 径流系数
  → 汇流响应（加权滞后和）
  → 退水（指数衰减）
  → + 基流 + 传感器噪声 + 偶发缺失/异常
```

**收益**：① 降雨与水位具备可见因果与滞后，演示可信；② 生成器与模型同参，占位模型的表现自然合理，成本几乎为零；③ 支持注入极端降雨事件用于预警演示；④ 真实数据接入时只需替换 `DataSource` 实现。

### 8.1 降雨预报序列（V1.3 新增，支撑 6h/12h）

模拟源**同时产出两路降雨**：

```
rain_observed(t)            # 实况降雨（已有）
rain_forecast(t_issue, h)   # 在 t_issue 时刻对未来 h 小时的预报（新增）
```

预报误差建模，体现"预见期越长越不准"这一真实特性：

```
rain_forecast(t, h) = rain_true(t+h)·(1 + ε(h))
ε(h) ~ N(bias(h), σ(h))，σ(h) 与 |bias(h)| 随 h 单调增大
```

可额外加入**对峰值的系统性低估**（真实数值预报对强对流的典型缺陷），让演示更真实。

**由此 6h/12h 从"占位"升级为"本期跑通"**——完整链路（预报输入 → 预测 → 研判 → 预警）全部可演示，且能直观看到**预见期越长、置信区间越宽**。真实场景接 NWP 时，只需替换 `rain_forecast` 的取数实现。

**研判侧配套（长预见期降权）**：6h/12h 生成的预警标记 `is_reference = 1`（参考级），界面浅色区分、不计入有效预警统计、默认不推送，避免因长预见期不确定性造成误报风暴。

**若需撤回**：`config.yaml` 中 `lead_hours: [1,3,6,12]` 改为 `[1,3]` 即可，代码不改。

## 9. 异常处理

| 异常 | 处理 |
|---|---|
| 数据源断流/超时 | 置 `ERROR`、暂停预测、前端降级提示、恢复后自动重连 |
| 模型推理失败 | 捕获异常 → 返回最近一次有效预测并标注"数据延迟" |
| 数据库写入失败 | 记录日志 + 内存缓冲重试 |
| 长任务失败 | `task` 表记录失败原因，可查询 |
| 未知异常 | 全局异常处理器 → 统一 `{code, message, data}` + trace_id 落日志 |

## 12. 演进路径

1. **接真实数据**：实现 `RealSourceAdapter`，改配置 `datasource.type: real`
2. **换真模型**：新增 `LgbmModel` 实现 `ForecastModel`，改配置 `forecast.model: lgbm`
3. **接入 Agent-B**：实现 `Agent` Port（LangGraph 或自研），复用已有 `ToolRegistry`
3b. **升级 Agent-A**：`RuleBasedOrchestrator` → bandit/RL 选模型或 LLM 生成策略，调用方不变
3c. **接真实 NWP**：替换 `rain_forecast` 的取数实现，6h/12h 链路无需改动
4. **暴露 MCP**：`api/mcp/` 填充实现，外部 Agent 客户端可直接调用
5. **加精度评估**：基于 `forecast_point.actual_level` 回填，无需改表结构

以上五步**均不需要修改应用层与领域层代码**——这是 V1.2 架构的全部价值所在。
