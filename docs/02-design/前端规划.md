# 水位预测预警系统 —— 前端规划书

**版本**：V2.1（替代 v0.1；依据《需求分析与技术选型》V1.1、《架构升级与Agent预留设计》V1.2、《需求覆盖核对与缺口补齐》V1.3、《后端规划书》V2.1）
**日期**：2026-10-03
**定位**：Web 展示端——呈现"水位历史 + 预测曲线（原始 vs 修正）+ 预警状态"，验证"预测 → 协同修正 → 预警"链路，并为后续 Agent 控制台预留页面位

## 2. 技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | **Vue 3（组合式 API）+ TypeScript** | TS 是 V1.2 新增：Agent 返回结构化数据，类型安全是刚需 |
| 构建 | Vite | 快、配置简单 |
| UI | Element Plus + 按需自动导入 | 后台管理组件齐全；配 `unplugin-vue-components` 做按需 |
| 图表 | ECharts（封装为组合式函数） | 水位曲线、预警四色、双曲线线型区分 |
| 状态 | **Pinia** ⚠️ V1.1 曾决定不引入，V1.2 反转 | 反转理由见 §2.1 |
| 路由 | Vue Router 4 | 五个页面路由 |
| 工具库 | VueUse | 轮询、防抖、本地存储等 |
| HTTP | fetch 封装 + **openapi-typescript 生成的类型/client** | 契约单一事实来源，杜绝手写不同步 |
| 流式 | **SSE**（预留） | Agent token 流；比 WebSocket 更简单，浏览器原生自动重连 |
| Mock | `VITE_USE_MOCK` 双通道 | 后端未启动时页面仍可演示 |
| 数据请求缓存 | 轻量自研 composable | 不引入 TanStack Query，保持依赖精简 |

### 2.1 关于 Pinia 的反转

V1.1 决定"不引入 Pinia（状态规模小）"。**V1.2 反转**：

1. **Agent 会话是跨页面共享的有状态数据**——会话列表、当前消息流、流式接收中的 token，组件本地 ref 无法管理；
2. SSE 流式输出需要在组件外累积状态；
3. 引入成本仅一个轻量库，后期补做要改大量组件。

> 属于"新需求（Agent）导致的前置条件变化"，不是决策反复。已在架构文档中记录原因。

### 2.2 为什么用 OpenAPI 生成类型

后端 FastAPI 自带 OpenAPI schema，一条命令即可生成前端类型与请求封装：

```bash
npm run gen:api     # openapi-typescript http://localhost:8000/openapi.json -o src/api/schema.d.ts
```

**收益**：后端改字段，前端类型立即报错，不会静默不同步。这在将来 Agent 返回复杂结构化结果时尤其关键。成本只是一个 devDependency 与一条 npm script。

## 3. 页面结构

### 3.1 总览页 `/`

```
┌ 顶部状态条：数据源连接状态 · 当前模型 · 今日预警统计 ┐
│  监测点卡片网格                                     │
│  ┌────────┐ ┌────────┐ ┌────────┐                │
│  │ 名称    │ │ 名称    │ │ 名称    │                │
│  │ 当前水位│ │ 当前水位│ │ 当前水位│                │
│  │ 预警色标│ │ 预警色标│ │ 预警色标│                │
│  └────────┘ └────────┘ └────────┘                │
│  最近预测记录列表                                   │
└───────────────────────────────────────────────────┘
```

- 卡片按预警等级排序（红 > 橙 > 黄 > 蓝 > 正常）
- 点击卡片 → 详情页
- 后端不可用时顶部显示降级横幅，卡片显示 mock 数据

### 3.2 监测点详情 `/station/:id`（V2.1 扩展）

```
┌ 点位信息 + 当前预警徽标 + 预警提前量 + 参考级标记 ┐
│  水位趋势图（ECharts）              │
│   · 历史水位（实线）                │
│   · 原始预测曲线（细虚线，V2.1）      │
│   · 修正后预测曲线（粗虚线，V2.1）    │
│   · 四级阈值线（蓝/黄/橙/红）       │
│   · 置信区间（半透明带，随预见期展宽）│
│  预见期切换：1h / 3h / 6h / 12h     │
│  预测摘要：峰值水位 · 峰值时间 · 置信区间 │
│  「发起预测」按钮 · 模型切换下拉（S7）   │
│  Agent-A 决策面板（为何选此模型/融合权重/修正强度） │
│  最近预测记录                       │
└────────────────────────────────────┘
```

- **模型切换下拉**是场景 S7「模型可插拔演示」的前端承载：切换后重新预测，曲线变化，直观证明业务代码不改
- **预见期切换**：1h/3h/6h/12h 全支持，切换后重新发起预测；**预见期越长置信区间越宽**（V2.1，直观展示不确定性传播）
- **双曲线**：原始预测（细虚线）与修正后预测（粗虚线）同屏，修正效果一眼可见（V2.1，多源协同修正的证明）
- **参考级预警**：6h/12h 触发的预警带"参考"徽标、浅色显示，不与有效预警混排统计（V2.1）
- **Agent-A 决策面板**：展示 `GET /forecasts/{id}/decision` 返回的模型选择、融合权重、修正强度与理由（V2.1，"智能体特性"的最直观证明）
- 预警提前量展示："本次预警较阈值报警提前 XX 分钟"

### 3.3 预警中心 `/alerts`

- 预警记录列表（时间倒序）：等级色标、监测点、触发原因、预见期、状态
- **参考级预警浅色区分，可独立筛选**（V2.1）
- 筛选：等级、时间范围、状态（生效 / 已解除）
- 点击 → 跳转对应监测点详情

### 3.4 系统设置 `/settings`

- 监测点管理（增删改、四级阈值配置）
- 数据源配置（类型 simulated/real、采集间隔）
- 模型管理（版本列表、激活入口、**参数校准入口 → 展示前后误差对比**（V2.1）；重训入口 → 提示"功能建设中"）
- 系统信息（健康检查三态）

### 3.5 Agent 控制台 `/agent`（V1.2 新增，占位）

```
┌ 会话列表 │ 消息流 │ 工具调用轨迹面板 ┐
```

- 本期用 `EchoAgent` + mock 演示完整链路：**提问 → 命中工具 → 执行 → 回答**
- 右侧工具调用轨迹面板是加分项——能直观看到 Agent 选了哪个工具、传了什么参数、返回了什么
- 页面骨架 + 流式接收 composable 做实，推理能力待后端填充

> **这个页面即使后端 Agent 是占位的也有价值**：它证明了前端已具备承载 Agent 的能力，剩下的只是后端填推理实现。

## 5. 数据交互

### 5.1 统一请求封装

```ts
// api/client.ts 核心逻辑
const res = await fetch(url, opts)
const body = await res.json()
if (body.code !== 0) throw new BizError(body.code, body.message)  // 禁止只看 HTTP 200
return body.data
```

业务错误码非 0 一律抛错，由页面捕获后展示降级提示。**这条是硬约束**。

### 5.2 刷新策略

| 数据 | 策略 |
|---|---|
| 监测点状态与水位 | 轮询 30 s（`usePolling` 封装，页面隐藏时暂停） |
| 预警列表 | 轮询 30 s；有新预警时顶部提示 |
| 预测结果 | 用户触发（点"发起预测"）+ 模型切换时重新预测 + 预见期切换时重新预测 |
| Agent-A 决策 | 随预测结果一并返回（predict 响应含 decision 段），不单独轮询 |
| Agent 消息流 | SSE 流式（预留），不可用时降级为一次性返回 |

### 5.3 降级处理

| 场景 | 表现 |
|---|---|
| 后端未启动 / 网络失败 | 顶部降级横幅 + 使用 mock 数据，**不白屏** |
| 业务错误码（如 MODEL_NOT_READY） | 页面内提示具体原因，不吞掉错误 |
| 数据源断流 | 状态条显示断流，水位数据标注"数据延迟" |
| SSE 不可用 | 自动降级为普通请求 |
| 决策面板无数据 | 隐藏面板或显示"本次预测无编排决策记录" |

## 7. Mock 双通道

`VITE_USE_MOCK=true` 时所有请求走 `mock/fixtures`，返回结构与后端契约一致（类型共用 `schema.d.ts`）。

**收益**：
1. M3 阶段可与后端并行开发，不互相阻塞
2. 演示时后端故障也能讲完所有页面
3. **Agent 控制台在后端推理未实现时即可演示完整交互链路**

Mock 数据需覆盖：正常场景、无预警场景、多等级预警场景、数据源断流场景、极端暴雨场景、**协同修正生效场景（原始 vs 修正差异可见）**、**6h/12h 参考级预警场景**、**Agent-A 决策场景（融合权重随数据源状态变化）**（V2.1）。

## 9. 演进路径

1. **接真实 Agent**：后端填充 `Agent` Port 后，前端只需打开真实接口开关，`useSSE` 接收流式消息，页面无需改动
2. **加地图**：须先解决离线瓦片与合规审图号，再引入 Leaflet / 本地 GeoJSON
3. **移动端**：响应式断点改造，桌面布局不受影响
4. **多站点对比视图**：复用 `TrendChart` 组合式封装
5. **决策可视化增强**：Agent-A 升级为 RL/LLM 后，决策面板扩展为"决策过程时间线"
